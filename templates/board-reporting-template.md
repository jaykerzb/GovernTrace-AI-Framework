# AI Governance Board / Executive Report

A periodic (recommended quarterly) reporting template for the [Governance Lead](../docs/roles-and-raci.md) to brief leadership or the board. Keep it to one or two pages — the point is a fast, honest signal on AI risk posture, not a data dump.

## Reporting period

| Field | Value |
|---|---|
| Period covered | |
| Prepared by | |
| Date | |
| Current maturity level (see [Maturity Model](../docs/maturity-model.md)) | |

## 1. Headline summary

Two or three sentences: is AI risk trending better, worse, or steady this period, and why?

|---|---|

Call out anything rated **High** risk or above specifically — one line each on what it is and why it's approved/pending.

## 4. Incidents

| Severity | Count this period | Notes |
|---|---|---|
| Sev 1 — Critical | | |
| Sev 2 — High | | |
| Sev 3 — Moderate | | |

Link to closed [Incident Response Runbook](incident-response-runbook.md) records for anything Sev 1/2. Flag any unresolved Sev 1/2 items explicitly — don't bury them in a table.

## 5. Vendor/third-party posture

- New vendors onboarded this period, and their risk rating (see [Vendor Due Diligence](vendor-due-diligence.md))
- Any vendor incidents, security disclosures, or contract/policy changes affecting your risk exposure

## 6. Compliance posture

Brief statement on standing against the frameworks you track — see [standards crosswalks](../docs/standards/) for detail. Example:

- NIST AI RMF: [e.g., "Govern and Map functions well-covered; Measure remains partial — no dedicated bias-testing resourcing yet"]
- EU AI Act (if applicable): [any systems newly identified as High-risk under the Act]
- ISO/IEC 42001 (if pursuing): [status, if applicable]

## 7. Gaps and asks

What does the Governance Lead need from leadership this period? (budget, headcount, a policy decision, executive sign-off on a High-risk system, etc.) Be specific — a vague "more support" ask doesn't get funded.
